# Проект: Рекламации — расширение к «1С:Бухгалтерия предприятия 3.0» (учебная)

Общие правила — в `C:\Dev\CLAUDE.md` (подхватывается автоматически). Этот файл их дополняет.
Главное отличие от соседних проектов: здесь мы **не пишем свою конфигурацию**, а **дорабатываем типовую
через расширение**. Основную конфигурацию БП не менять никогда.

## Специфика проекта

- База: файловая, `C:\1c\bp_ucheb` — «1С:Бухгалтерия 8. Учебная версия» (БП 3.0 на БСП)
- Расширение: имя `Рекламации`, префикс `рек_`, назначение «Адаптация»
- `src\` — исходники **расширения** (Hierarchical). Это то, что мы правим и коммитим.
- `base-src\` — выгрузка **основной конфигурации БП**. Только для чтения, в git не идёт.
  Источник правды о типовых объектах и API БСП.
- Настройки путей — `.1c-devbase.ps1` (в git не идёт, шаблон `.1c-devbase.ps1.example`).

## Команды

```
dump.bat        база -> src        выгрузка расширения (первый раз полная, дальше инкрементальная)
load.bat        src -> база        загрузка расширения + /UpdateDBCfg -Extension + /CheckModules
dump-base.bat   база -> base-src   выгрузка основной конфигурации БП (долго; раз и после обновления БП)
```

Все три пишут лог в корень проекта: `dump.log`, `load.log`, `dump-base.log` (UTF-8 с BOM).
Скрипты — PowerShell в `tools\`, `.bat` — только запускалки.

## Правила работы с расширением

1. **Собственные объекты и реквизиты — только с префиксом `рек_`**: `Документ.рек_Рекламация`,
   реквизит `рек_КоличествоРекламаций` в заимствованном объекте и т.д. Без префикса при обновлении
   БП возможен конфликт имён.
2. **Заимствованные объекты XML-ом руками не создавать.** Их заимствует пользователь в Конфигураторе
   (ПКМ по объекту основной конфигурации → «Добавить в расширение»), затем `dump.bat`. Причина: в файле
   заимствованного объекта `ObjectBelonging=Adopted` и `ExtendedConfigurationObject` = uuid объекта из
   основной конфигурации — ошибка в нём ломает загрузку. Если нужно новое заимствование — попросить
   пользователя, дождаться выгрузки.
3. **Перехват типового кода** — в модуле заимствованного объекта, аннотациями:
   - `&После("ИмяПроцедуры")` / `&Перед("ИмяПроцедуры")` — предпочтительно;
   - `&ИзменениеИКонтроль("ИмяПроцедуры")` — только точечно, когда иначе нельзя (при обновлении БП
     платформа проверит, что исходный текст процедуры не изменился);
   - `&Вместо` — избегать: отключает типовую логику целиком.
   Имя процедуры-перехватчика — с префиксом: `рек_ОбработкаПроведенияПосле`.
4. **API БСП не угадывать.** Перед вызовом `ПодключаемыеКоманды`, `УправлениеПечатью`,
   `ОбщегоНазначения` и т.п. найти процедуру в `base-src\CommonModules\<Модуль>\Ext\Module.bsl`
   и прочитать её комментарий — сигнатуры меняются от версии к версии БСП.
   Версия БСП: `base-src\CommonModules\ОбновлениеИнформационнойБазыБСП\Ext\Module.bsl`,
   процедура `ПриДобавленииПодсистемы` (`Описание.Версия`).
5. **Переопределяемые модули БСП** (`...Переопределяемый`) заимствовать и дописывать через `&После`,
   не через `&Вместо`.
6. **Структуру типового объекта смотреть в `base-src`**, а не по памяти: реквизиты
   `РеализацияТоваровУслуг`, её табличные части, имена процедур в модуле объекта/менеджера.
7. **Режим совместимости расширения** не выше, чем у основной конфигурации. Не трогать в `Configuration.xml`.

## Что должно получиться (этап 1)

| Объект | Назначение |
|---|---|
| `Перечисление.рек_СтатусыРекламаций` | Новая, НаРассмотрении, Удовлетворена, Отклонена |
| `Справочник.рек_ПричиныРекламаций` | брак, недовоз, пересорт, повреждение упаковки … |
| `Документ.рек_Рекламация` | шапка: Организация, Контрагент, ДокументРеализации, Статус, Ответственный, Комментарий; ТЧ `Товары`: Номенклатура, Количество, Сумма, Причина |
| `РегистрНакопления.рек_Рекламации` (обороты) | измерения Организация, Контрагент, Номенклатура, Причина; ресурсы Количество, Сумма |
| `РегистрСведений.рек_ИсторияСтатусов` | независимый периодический: Рекламация → Статус, Ответственный (пишется кодом, не движениями) |
| `Отчет.рек_АнализРекламаций` | СКД: по номенклатуре / контрагентам / причинам, варианты отчёта |
| Печатная форма «Акт рекламации» | через подсистему «Печать» БСП |
| Команда «Создать рекламацию» в реализации | через подключаемые команды БСП (ввод на основании) |
| `Роль.рек_РаботаСРекламациями` | права на объекты расширения |
| Подсистема `рек_Рекламации` | раздел в интерфейсе |

Заимствовать (делает пользователь): `Документ.РеализацияТоваровУслуг`, `Справочник.Контрагенты`,
`Справочник.Номенклатура`, `Справочник.Организации`, `Справочник.Пользователи`; позже — общие модули
БСП для печати и подключаемых команд.

## Учебная версия + БП

- Лимит 2000 записей на таблицу касается и типовых справочников — демо-данные занимают часть лимита.
- Печать и сохранение табличных документов в учебной версии отключены — печатная форма
  формируется и показывается на экране, это нормально.
- Если в базе есть пользователи — имя вписать в `$ONEC_USER` в `.1c-devbase.ps1`, иначе пакетный
  запуск не войдёт.
